## 1. 全局状态模型与状态矩阵

### 1.0 自解释原则（陌生人测试，2026-10-11 用户指出后补立）

> 用户原话："如果我是个陌生人，你这个上位机不能让我知道你是什么系统。"

陌生操作员（未读过任何文档）在主画面停留 **10 秒内**应能回答四个问题；每个问题对应的界面义务：

| 问题 | 界面义务 | 落点 |
|---|---|---|
| 这是什么系统？ | 顶栏系统全称 + 工艺副标（"蓄水池 · 3 台水泵 · 阀门组监控"） | §2.1 |
| 监控/操作哪些对象？ | **每个图形对象必须有名称标签**：蓄水池、1#/2#/3# 水泵、总阀门、支阀、主管、汇管、主管输出 | §2.2 标签规范 |
| 现在正常吗？ | 顶栏通信 Chip + 报警徽章 + 状态徽章带（状态永可见，原则①） | §1.2 矩阵 |
| 水往哪流/颜色什么意思？ | 管路流向（箭头）+ **工艺图例**（流动/无水/运行/故障/停止）常驻过程卡左下 | §2.2 |

- 标签文案的来源纪律：**优先取 TagTable.csv 的 Description 列语义**（如"当前储水池水位"→"蓄水池"、"主管输出压力"→"主管输出"），不发明新名词——数据契约仍是唯一事实源；
- 此原则为 M4 的**验收门**：T4.2 增加"陌生测试"（实施细则 §2），任一图形对象无标签即不通过。

### 1.1 状态定义与判定（数据源全部已存在）

| 状态 | 判定 | 数据源 |
|---|---|---|
| S1 未连接 | 初始或主动断开，模拟未运行 | polling.IsConnected=false 且 SimRunning=false |
| S2 连接中 | 连接流程进行中 | ConnectAsync 任务未完成（对应"连接中…"，FrmMain.cs:402） |
| S3 已连接 | IsConnected && Quality=OK | DataPollingService.IsConnected + 质量 |
| S4 重连中 | Broken 后退避进行 | ReconnectAttempts>0 且未成功（Core 增只读属性） |
| S5 数据中断 | IsConnected 但 Quality=false | OnQualityChanged(false) 或 200ms 看门狗（FrmMain.cs:940-947） |
| S6 模拟运行 | 叠加态 | SimRunning=true（FrmMain.cs:467-531 语义） |

- **流动条件（B8 水路因果，用户裁定）**：进水段（MainValve 组）= 主阀开；泵支路 = 主阀开 **且** 该泵运行——"主阀门不开怎么会有水"；
- 阀体：主阀+3 支阀的阀体图形叠在管廊/卡内，开=Ok 点亮、关=Off。

### 2.9 通信卡（1102,648,384,180）——两态状态机

```
输入态 ──点[连接]──→ busy(连接中…) ──成功──→ 键值态
   ↑                    │失败                    │
   └──────点[断开]─────────────── 键值态 ←──────┘
   任意态 ──点[模拟]──→ 模拟运行（按钮变[停止模拟]）──再点──→ 断开回输入态
```

| 态 | 内部布局 |
|---|---|
| 输入态 | "IP" 标签(16,40)+输入框(48,36) 200×28；"端口"标签(16,84)+输入框(48,80) 200×28；按钮行 (16,128)：[连接 Accent][模拟 BgHover]——**标签与输入框同行左对齐（修 P3）** |

## 8. 组件策略（决策 D11：域控件自绘，基础件引库）

"UI 的组件怎么办"——按**工艺语义强弱**分三类处理，不搞一刀切：

| 类 | 组件 | 处置 | 理由 |
|---|---|---|---|
| **A. 自绘控件（12 个）** | 工艺语义 8：PipeLine、PumpGraphic、LevelTank、RingGauge、ParaBox、StatusBadge、AlarmBadgeChip、WaterTrendChart；开关 3：USwitchW、UJogSwitchW、URotarySwitchW；骨架 1：CardChrome | WPF UserControl 自绘，视觉按本文规格 | 工艺语义强（水路因果、报警联动、量程=TagTable），任何库都没有；渲染实证已验证自绘可行（§9） |
| **B. 基础件（引库）** | Card 边框、Button/确认框、TextBox、DataGrid 皮肤、全局深色资源、通知气泡 | **HandyControl**（MIT，NuGet `HandyControl`，.NET 8 实测可用，中文文档/社区活跃） | 无工艺语义，自绘纯费工；渲染实证恰好证明必要性——**原生 DataGrid 默认表头是白底**（PoC 第一轮即出现），逐个样式接管约 1~2 天；HC 提供现成深色皮肤 |
| **C. 混合（原生+样式）** | Canvas 设计稿画布、DataGrid 行着色（LogRowStyler 数据触发） | WPF 原生 + 令牌覆盖 | Canvas/触发器是框架原生能力，引库反而绕路 |

**D11 边界与风险**：
1. HC 只用于"壳"，**不引入其业务控件替代域控件**——避免 Zhaoxi 式绑定（源项目教训：控件库无 WPF 版导致整套 UI 重写）；
2. HC 会重写几乎所有默认控件样式（社区实测反馈），个别需要原生样式时"改回去较复杂"——缓解：T4.1 先做 HC 令牌对齐（把概要 §4.4 令牌映射到 HC 的资源键），T4.9 统一做深色一致性检查；
3. 版本锁定 `HandyControl` **3.5.1**（2026-10-11 实测：NuGet 可还原、HC 命名空间编译通过，迁移方案 §8-9）；MIT 无商用风险；
4. 若坚持"零第三方依赖"（源项目手写 Modbus 的自研哲学），B 类也可自绘——功能无损，工期 +1~2 天；**推荐引库**，把工时留给 A 类域控件和水路联动。

## 9. 渲染实证（PoC）与设计预览图

- **方法**：临时沙箱建 net8.0-windows WPF 工程（零第三方依赖），按本文令牌与坐标以代码构建主画面（含真实 DataGrid+BindingList 绑定与行着色触发器），`RenderTargetBitmap` 离屏渲染 1492×1000 → PNG；
- **结果**：编译零错误、渲染成功；深色令牌/CardChrome/环形仪表/管道流动层/状态徽章/报警四态 chip/日志行着色/趋势阈值线全部按设计出图。**预览图：[docs/design-preview.png](design-preview.png)**；
- **第二轮（v1.2，自解释原则落地）**：用户指出"陌生人认不出这是什么系统"——复检确认重设计弄丢了源界面的对象标注能力。已补：工艺副标/逐对象标签（蓄水池、主管、总阀门、启停、汇管→主管输出）/工艺图例/趋势卡标题达意化，预览图已更新为带标签版；标签均可在渲染中核对；
- **第一轮打磨记录**：
  1. 第一轮发现**不透明泵卡遮挡管路** → §2.2 改管廊布局（上廊主管/下廊汇管），泵卡 446→356；
  2. 原生 DataGrid 默认表头白底、星号列宽在无约束容器下不展开 → 支持 §8 组件策略 B（引 HC 或显式样式接管）；
  3. 管底色 #334155 在深卡上对比不足 → 令牌 PipeIdle 调至 `#3D4E6B`（回写概要 §4.4）；
  4. 环形仪表底部标签与环体重叠 → RingGauge 画布加高 14px 标签区（§3 规格同步）。
