## 0. 评审结论：当前 WinForms 界面满足"人性化"吗？

**结论：不满足。** 安全机制层是达标的（确认/回滚/fail-fast/诚实空态，见上表），但**信息呈现层有 18 项实锤问题**（P1~P18，P18"过程图对象无标注"为 2026-10-11 陌生人测试追加），其中 6 项属于硬伤：操作员做正确决策所需的信息**不可得或不可见**。全部问题均来自实际截图（`docs/screenshots/主界面.png`、`报警发生-主界面.png`）与代码实读，逐条可复验。

## 1. 设计原则（5 条，每条对应问题组）

| # | 原则 | 消灭的问题 |
|---|---|---|
| ① | **状态永可见**：通信状态、未确认报警数、运行模式常驻顶栏，任何时刻一屏内可判断"系统现在正常吗" | P4 P12 P13 |
| ② | **一个数据一个真相**：同一 Tag 的多处显示同源同值；数值按精度规范格式化；单位全屏统一 | P1 P2 P7 P8 |
| ③ | **就近原则**：泵数据在泵旁、标签贴着输入框、灯的文字随状态变（阀门灯显示"开/关"） | P3 P6 P9 |
| ④ | **颜色 = 状态**：正常态低饱和；红/黄/绿只给运行与报警状态；报警对象在过程图上描红 | P4 P7 |
| ⑤ | **防误触优先**：确认弹窗默认焦点在"取消"、退出要确认、按钮互斥启用、重连/连接有进行时反馈 | P13 P14 P16 |
| ⑥ | **自解释（陌生人测试）**：每个图形对象有名称标签、介质与流向可读、工艺图例常驻——10 秒内回答"这是什么系统/监控什么/正常吗/水往哪流" | P18 |

### 1.5.2 为什么深色卡片式与"人性化"不冲突（检索佐证）

ISA-101（高性能 HMI 标准）的通行做法正是：**单一深灰/黑底降低长时值守眩光；正常态设备一律低对比灰调（靠形状与位置传达信息）；饱和色只留给异常**——"gray by default, color for exceptions"。参考图的深色方向与标准同向；要守住的只有一条：**正常态别抢戏，红/黄只给报警**。本项目 P4（报警主画面无感）的修复在深底上反而更醒目。图①的霓虹装饰发光属"展示大屏风"，生产值守界面按上表"克制"行处理。

检索来源：HRSD 自动化标准（ISA-101 深底/灰调/报警色规则）、HMI Library（ISA-101 风格解读）、ThingsBoard SCADA 泵状态监控范例、3D-SCADA 泵卡/仪表组件范例、AVEVA 泵站面板文档、Dribbble/Pinterest SCADA 视觉集。

## 8. 明确不做（防发明危险功能）

1. **确认弹窗不可跳过**、不可"记住选择"——控制指令的最后一道人关，不做免确认选项；
2. **不自动写值**：任何 UI 改动不得让界面在无人操作时产生写指令（回写防护专项测试继续把关）；
3. **不动服务层语义**：报警生命周期、控制三阶段决策、fail-fast 校验、轮询/退避参数全部原样；
4. **不做多主题/多语言**（沿用 v4 取舍）——深色即唯一主题；
5. **不做组态化编辑器**（拖拽组态列入远期，沿用 v3 取舍）；
6. **装饰发光克制**：深色卡片的霓虹效果仅限悬停/选中反馈，不得用于状态表达（状态只认 §4.4 色板）。
