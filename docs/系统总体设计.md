## 1. 分层架构（依赖只允许向下，事件只允许向上）

```
┌─────────────────────────────────────────────────────────────────────┐
│ L6 表现层  MainWindow / ProcessCanvas / 12 自绘控件 / LogViewer / 对话框 │  ← 把状态渲染成像素
├─────────────────────────────────────────────────────────────────────┤
│ L5 应用层  App(组合根) / MainViewModel / ControlViewModel /          │  ← 状态唯一属主
│            AlarmPanelVM / LogViewerVM / AppStateStore / TagBinding   │    行为编排与封送
├─────────────────────────────────────────────────────────────────────┤
│ L4 业务层  DataPollingService / ControlService / ControlDecision /  │  ← 领域逻辑
│            AlarmService / AlarmCenter / LogService / ValueFormatter  │    不知道 UI 存在
├─────────────────────────────────────────────────────────────────────┤
│ L3 通信层  ModbusClient(三态会话/两阶段读/超时/串行化) /             │  ← 帧协议与字节
│            ModbusFrame / CommStatistics                              │    不知道 Tag 语义
├─────────────────────────────────────────────────────────────────────┤
│ L2 契约层  TagTableLoader(E01~E09) / TagAddress / AlarmConfig       │  ← 唯一事实源
│            (A01~A09) / Utility / AppConstants                        │    fail-fast 拒绝带病启动
├─────────────────────────────────────────────────────────────────────┤
│ L1 模拟层  ModbusServer / ProtocolProcessor / DataStore /           │  ← 与 L3 对等的从站
│            ScenarioEngine / ModbusSlaveSim(劣化注入)                 │    供无硬件全链路运行
└─────────────────────────────────────────────────────────────────────┘
   支撑：持久化（history.db / app_init.json / logs/*.log）+ 配置（TagTable.csv / AlarmConfig.json / Communication.txt）
   展示支撑：HandyControl(D11 基础件壳) + Dark 令牌
```

- **依赖方向**：上层引用下层（L6→L5→L4→L3→L2）；L1 模拟层不依赖任何上层，对 L3 而言它就是"一台 PLC"。
- **事件方向**：下层只发事件/回调（OnDataReceived/OnConnectionChanged/OnQualityChanged/OnStatusChanged/OnAlarmChanged/OnEntry/OnError），上层订阅——下层永远不知道谁在听。
- **双模式不分叉（D5）**：模拟与真机的差异只有一处——连接目标（127.0.0.1:1502 进程内从站 vs PLC IP）；协议栈/服务/界面完全同一路径。禁止"演示专用"特殊逻辑（源仓库 AGENTS.md 产品定调）。

## 2. 模块职责总表（每一块在做什么 / 不做什么 / 上下游）

> 边界列 = 单一职责的"不做什么"；争议以此表为准。

### L2 契约层（唯一事实源）

| 模块 | 在做什么 | 不做什么 | 上下游 |
|---|---|---|---|
| TagTableLoader | 加载 36 点标签表并 fail-fast（E01~E09/W01~W03 全量报出）；`CheckUiBindings` 收**字符串集合**做 UI 绑定核对 | 网络、UI、报警 | 上游 TagTable.csv；下游 轮询/控制/VM/绑定注册表 |
| TagAddress(+Type/Access) | 单点在 Modbus 地址空间中的定位：地址/类型/读写性/寄存器数/Scale/量程/单位/描述 | 值的计算 | 上游 Loader；下游 全系统 |
| AlarmConfig.Load | 报警阈值加载 + A01~A09 fail-fast + 部分覆盖/注释容错 | 报警评估 | 上游 AlarmConfig.json；下游 AlarmService |
| Utility | Communication.txt 解析（IP:Port，容错缺省） | 校验fail-fast（文件缺失仅缺省） | 上游配置文件；下游 组合根 |
| AppConstants | 全局常量唯一出处（轮询 1s/IO 超时 2s/字序 CDAB/批量上限…） | 任何逻辑 | 被所有层引用 |

### L3 通信层（字节与协议）

| 模块 | 在做什么 | 不做什么 | 上下游 |
|---|---|---|---|
| ModbusFrame | MBAP/PDU 组帧与解析纯函数（两阶段精确读的依据） | 连接管理 | 下游 ModbusClient |
| ModbusClient | TCP 会话三态（Connected/Broken/Disconnected）、两阶段精确读、TID 校验、CancellationToken 真超时、SemaphoreSlim 串行化、读/写四功能码、LastError | 重连决策（L4 轮询的事）、Tag 语义 | 下游 轮询/控制；上游 L1 模拟器或真 PLC |
| CommStatistics | 请求/成功/失败/字节/RTT/重连计数（通信卡键值数据源） | 呈现 | 上游 ModbusClient；下游 通信卡 |

### L4 业务层（领域逻辑）

| 模块 | 在做什么 | 不做什么 | 上下游 |
|---|---|---|---|
| GroupPlanner | 地址分组纯函数（间隔≤8 合并、跨度校验） | 收发 | 上游 TagAddress；下游 轮询 |
| RegisterCodec | 字序参数化（CDAB/ABCD）解码/编码纯函数 | 缩放（Scale 由调用方） | 下游 轮询/模拟器 |
| DataPollingService | 轮询编排：定时→防重入→断线指数退避重连(1s→30s)→分组批量读→解码+Scale→DataPoint 字典→事件广播；质量事件；LastGoodPollAt | UI、控制、确认 | 上游 ModbusClient；下游 VM |
| ControlService | 写线圈唯一出口：连接/标签存在/读写权限三检查 | 确认与回滚决策（ControlDecision） | 上游 ControlViewModel；下游 ModbusClient |
| ControlDecision | 控制三阶段纯函数：Precheck/ResolveConfirmation/PostWrite + 自翻转语义 + 文案 | IO、弹窗 | 上游 ControlViewModel；被 110 项测试中的决策测试锁定 |
| AlarmService | 阈值评估：本轮活跃集 vs 上轮 → **增量**触发/恢复（AlarmInfo） | 存储、呈现、确认 | 上游 轮询数据 + AlarmConfig；下游 AlarmCenter/VM |
| AlarmCenter | ISA-18.2 生命周期（Raise/Clear/Acknowledge/AcknowledgeAll）+ SQLite 落库 + 计数（Unacknowledged* 徽标数据源）+ 存储失败降级 | 阈值判断 | 上游 AlarmService；下游 报警卡/徽标/F12 确认 |
| LogService | 日志三层分流：文件(全量)/Entries(BindingList, INFO+)/OnEntry(全量事件) | 着色（LogRowStyler）、UI | 被所有层调用 |
| ValueFormatter（Core 新增） | Scale→小数位、格式化纯函数（修 P1） | 单位映射（显示层） | 下游 ParaBox |

## 3. 四条数据流（系统怎么协同）

```
监视流（每 1s）：
PLC/模拟器 → ModbusClient(分组批量 0x03/0x01) → DataPollingService(解码+Scale)
  → OnDataReceived → MainViewModel(TagValues/徽标/首包同步) → 绑定 → 控件像素

控制流（用户手势，事件写）：
点击旋钮/开关 → ToggleCommand → ControlDecision.Precheck(连接/只读/存在)
  → ConfirmDialog(默认焦点=取消) → ResolveConfirmation → ControlService.WriteCoil(0x05)
  → PostWrite(失败回滚+ERROR 日志) → 下轮轮询回流确认（闭环）

报警流（增量）：
轮询数据 → AlarmService.Evaluate(阈值) → 增量 Raise/Clear
  → AlarmCenter(生命周期+SQLite) → OnAlarmChanged
  → 三处可见：顶栏徽标 / 实时报警卡 / 过程图对象描红（P4）
  → 双击/确认 → Acknowledge(id, Windows 用户名) → 落库

日志流（全链路可追溯）：
任意层 Log(level,msg) → LogService → 文件(全量) + BindingList(INFO+) + OnEntry(全量→F12)
```

**状态体系**：全局 S1~S6（未连接/连接中/已连接/重连中/数据中断/模拟运行）× 各区域显示义务 = 设计书 §1.2 状态矩阵；局部状态机（通信卡两态、泵三态、报警四态）各有映射表。**任何一个像素都应能指出它属于哪条流、哪个状态。**
